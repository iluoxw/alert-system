#### scheduler per-timer 事务重构（Bug B，架构级）
- **Purpose:** 🚨 修复生产级死锁：原 pollOnce 单事务锁整批 due 行后同步调 handler，handler 自开事务 UPSERT 同 (kind,ref_id) pending 行→跨连接循环等待，PG 死锁检测器看不到，唯一 worker 永久焊死（升级策略≥2级必现）。新模型：每定时器独立事务，SELECT..FOR UPDATE SKIP LOCKED LIMIT 1 → 先 markFired 再调 handler（同事务）→ 成功提交/失败整体回滚另开小事务 markFailed。markFired 前置是第二层 bug 的解：handler 续期 UPSERT 否则命中正在处理的同一 pending 行，随后 markFired 会把续期清掉。handler 必须幂等（at-least-once）且绝不能自开事务
- **Location:** internal/scheduler/scheduler.go
- **Signature:** type Handler func(ctx context.Context, tx pgx.Tx, refID string, payload []byte) error（旧签名无 tx）；五个 handler（oncall.Chain.Handle/notify.Engine.Handle/LifecycleHandlers.HandleTTL/HandleRepeat/pipeline.GroupStage.Handle）均改用传入 tx，txRunner 依赖已删
