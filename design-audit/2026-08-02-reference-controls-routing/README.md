# 受管引用与运行导航审计

日期：2026-08-02

范围：运行总览、故障、事故、告警移交，以及全局表单中的受管对象引用。

## 结论

1. 原“运行总览 / Faults / Incidents”只是同一页面的标题与滚动焦点别名，无法表达整体态势、技术判断、组织协作三个不同任务。现已拆为 `/`、`/faults`、`/incidents` 三个独立路由和页面。
2. 告警移交要求手输用户名或团队标识，但后端实际只更新处理人 `acked_by`。现已改为从登录级用户目录选择已登记成员，不提供语义不真实的团队选项。
3. Incident Cleanup 的“停止重试确认人”同属用户引用，已同步改为成员选择器。
4. 周期任务与值班安排的 IANA 时区属于有限标准值，已统一改为可搜索时区选择器。
5. 一级菜单及对应页面标题统一为中文：运行总览、故障、事故、告警、服务；Alertmanager、Webhook 等产品名或协议名保留原文。

## 页面职责

| 入口 | URL | 回答的问题 | 主要内容 |
|---|---|---|---|
| 运行总览 | `/` | 整体正在发生什么，先看哪里？ | 受管版图、活动故障、确认影响、响应中事故、优先判断项 |
| 故障 | `/faults` | 哪个技术故障应先判断，证据和爆炸半径是什么？ | 完整活动故障队列、影响排序、快速判断、应用影响 |
| 事故 | `/incidents` | 哪些事故已进入组织协作，生命周期走到哪一步？ | 状态计数、响应中/已解决筛选、事故响应队列 |

## 表单分类

| 字段类型 | 处理原则 | 示例 |
|---|---|---|
| 受管对象引用 | 使用目录驱动、可搜索的 Select | 移交处理人、停止重试确认人、团队、服务、关联故障 |
| 标准有限枚举 | 使用选择器 | IANA 时区、严重度、状态、角色 |
| 外部系统目标 | 保持自由输入并做格式校验/脱敏 | Webhook URL、飞书 open_id、邮件地址 |
| 解释与证据 | 保持自由文本 | 备注、裁决依据、恢复证据、工单引用 |
| 尚无目录 API 的白名单标识 | 暂不伪造下拉；先补服务端目录 | UAT 环境 ID、模板 ID、故障类型 taxonomy |
