# Firebreak 品牌接入与移动端审计

审计日期：2026-08-04
审计范围：登录、公共应用壳层、运行总览、故障队列、事故队列、控制中心、控制中心弹窗
验证视口：390 × 844 CSS px（手机），1440 × 900 CSS px（桌面回归）

## 结论

本轮已解决移动端的结构性阻塞，并将 Firebreak 图标、横向徽章、favicon 与 Apple Touch Icon 接入真实界面。手机视口不再被强制扩展为 720px，导航从不可操作的 72px 空侧栏改为抽屉，顶部搜索成为独立一行，核心运行态、故障和事故队列改为手机可读卡片布局；表格类管理页面仅在表格区域保留横向滚动。

- `06-navigation-drawer.png`：移动导航抽屉、当前路由与用户区。

## 发现与处理

### [已解决 P1] 视口被强制扩展到 720px

- 位置：`web/src/index.css` 的 `body`。
- 证据：390px 浏览器截图仍输出 720px 宽页面，用户必须横向查看缩小后的桌面布局。
- 处理：将全局最小宽度降为 320px，并让内容区、搜索框、网格和弹窗以可收缩轨道布局。

### [已解决 P1] 窄屏导航不可用

- 位置：`web/src/App.tsx` 的窄屏分支。
- 证据：旧版保留 72px 空侧栏，同时禁用“展开主导航”按钮。
- 处理：手机端完全移除持久侧栏，菜单按钮打开 280px 抽屉；选中路由后自动关闭，保留退出登录入口与当前用户信息。

### [已解决 P2] 顶部栏在手机上挤压标题和搜索

- 位置：`.app-topbar`、`.app-topbar__context`、`.app-topbar__actions`。
- 处理：手机端采用上下两行，第一行放菜单、页面标题和环境，第二行放全宽搜索与刷新；交互按钮提升到 40px 触控尺寸。

### [已解决 P2] 运行态与响应队列仍按桌面密度呈现

- 位置：运行总览、故障、事故页面。
- 处理：运行态摘要改为 2×2；故障表改为手机卡片行；事故元数据改为三列紧凑区；桌面端原有信息密度保持不变。

### [已解决 P2] 管理表格和弹窗会扩大整页

- 位置：控制中心资源表格、Alertmanager 数据源表格、Ant Design Modal。
- 处理：横向滚动限制在表格容器内；卡片标题/操作在窄屏堆叠；弹窗宽度限制为 `100vw - 24px`，正文独立滚动且底部操作保持可见。

## 品牌资产

- `web/public/brand/firebreak-icon.png`：512 × 512，导航图标。
- `web/public/brand/firebreak-badge.png`：960 × 224，登录徽章。
- `web/public/brand/firebreak-favicon.png`：32 × 32。
- `web/public/brand/firebreak-apple-touch-icon.png`：180 × 180。

资产由内置图像生成流程基于选定 Firebreak 品牌板生成，使用纯色键背景后本地去色键、收边、裁切和多尺寸导出；未使用手绘 SVG 或 CSS 图形替代品牌资产。

## 验证结果

- 登录：管理员登录成功并进入运行总览。
- 导航：移动抽屉可打开，故障入口可导航且抽屉自动关闭。
- 页面：运行总览、故障、事故、控制中心均在 390px 宽度下无整页横向溢出。
- 弹窗：登记 Alertmanager 数据源弹窗可见、可滚动、底部操作可达。
- 桌面回归：1440 × 900 下侧栏、顶部栏和主内容比例正常。
- 浏览器控制台：无 error/warning，仅有 Vite 连接与 React DevTools 开发提示。

## 后续 P3

- 当前品牌源是高分辨率 PNG。若后续确定正式商标交付，应由设计源补充官方矢量母版，并由构建链生成多尺寸位图；不影响本轮界面使用。
- 管理表格在手机上保留局部横向滚动，这是对高密度运维数据的有意取舍；后续可按使用频率为个别表格补充专用卡片视图。
