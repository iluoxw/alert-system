# 控制中心导航与周期任务交互设计

## 目标

把 SRE Control 从“所有页面都塞进左侧菜单”的管理后台，调整为工业化、克制、高密度的事故响应工作台：一级导航表达日常任务，低频配置集中到控制中心，页面内交互围绕明确的操作对象组织。

## 方案比较

### A. 继续压缩现有侧栏与横向 Tab

改动最小，但两个导航层级仍重复；设置项继续增长后还会再次溢出。不采用。

### B. 全局侧栏只保留“控制中心”，设置页使用分组垂直导航（推荐）

一级导航稳定，设置资源可按领域扩展；当前所在位置有唯一选中态，中等屏幕可以自然退化为 Select。采用。

### C. 使用命令面板替代大部分导航

对熟练用户高效，但发现性不足，不能作为唯一入口；可在后续全局搜索阶段作为增强，不纳入本轮。

## 信息架构

### 全局侧栏

- 运行：运行总览、Faults、Incidents、Alerts。
- 响应：静默策略。
- 管理员：控制中心。
- 服务、拓扑、Entity 治理在具备可用页面前不进入一级导航。

### 控制中心

- 数据与模型：数据源与渠道、Alert Mapping。
- 组织与责任：团队与服务、用户。
- 响应策略：值班安排、升级策略、通知策略。
- 自动化：周期任务。

设置页桌面端使用左侧 216px 分组导航，内容区保留页面标题和说明；小于约 980px 时改为顶部单一 Select。

## 周期任务交互

1. 顶部“配置范围”选择团队，并展示配置按团队生效。
2. 基础配置只保留时区。
3. 日报、陈旧告警清扫和值班播报分别作为任务行：标题、说明、启停状态和唯一参数横向对应。
4. 任务关闭时，时间或间隔控件同步禁用，但保留当前值以便重新开启。
5. 所有 Switch 和 TimePicker 提供唯一可访问名称。
6. 切换团队时若有未保存改动，必须确认是否放弃。
7. 保存按钮仅在有变更时可用；保存成功后恢复干净状态。
8. 通知渠道使用结构化列表，空状态明确说明任务启用后需要投递目标。

## 视觉方向

采用“industrial/utilitarian”而非装饰性仪表盘：深色任务侧栏、浅色控制面、明确的 1px 边界、低圆角、紧凑字号和数据对齐。重点状态只用蓝、绿、橙、红四类语义色；不引入渐变大卡片、无意义阴影或额外插画。

## 验收

- 设置页只有一个明确的当前选中入口，不再出现八个横向 Tab。
- 1280px 桌面宽度不截断控制中心导航；窄屏仍可访问所有设置资源。
- 关闭任务时参数不可编辑；开启后恢复。
- 团队 Select 可通过 role/键盘稳定选择；所有 Switch、TimePicker 名称唯一。
- 未保存变更切换团队出现确认；保存成功后按钮禁用。
- 前端 build、lint 与真实浏览器逐步截图验收通过。
