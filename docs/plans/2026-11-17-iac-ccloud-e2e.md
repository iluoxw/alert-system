# IAC 自动告警 CCloud 取证与端到端验收

关联 Issue #38。基线为 main `3b265759f5c1c9290ce20b480b02260298f1e767`。

## 已确认断点与决策

自动告警使用无原生工具的 OMA Agent，由 SRE 固定 broker 执行 IAC 指标查询；独立日报的 ccloud-cli 不会自动进入该链路。用户选择延续固定取证接口，不把告警 Agent 改成任意 shell 执行器。

流程为：Grafana 合成验收规则 → 原生 webhook → SRE 持久角色队列 → OMA 固定查询意图 → 宿主官方 ccloud-cli → 既有固定只读代理 → 证据账本 → 同一 OMA 会话 → SSE 事件持久化与结构化报告。

## 迭代

1. 增加 `ccloud_l4`，固定 argv、资源范围、严格响应校验和最小环境；仅向子进程传现有代理窄令牌。独立记录 CCloud 包/入口来源摘要，不借用 IAC Go CLI 摘要。
2. 通过现有 CCloud 开关装配新能力。关闭时保留旧 profile 与完成语义；开启后缺依赖或权限必须 unknown，不能静默移除取证项。开启时验收规则确定性要求 L4，正常业务 profile 在六查询预算内加入；两个满额 profile 用 L4 替换 sources 探活。保留入口/VIP覆盖项；来源异常仍仅允许 sources/freshness。
3. API 与可选 worker 镜像打包固定官方 CLI、Node 与依赖；构建期核验归档和文件清单，运行期不下载。现有构建入口明确接入离线材料。
4. 独立审查、回归测试和 CI 后合并发布，再跑 firing/resolved 完整链路并清理。

## 验收条件

- 新增单元测试覆盖固定命令、环境哨兵、严格字段/非零退出/超时/超限/缺配置失败闭锁；开启和关闭行为、六查询预算及来源异常限制有回归。
- 固定 CLI 包可冷启动获取 metadata 并完成 Pod 查询，证据有当前采样时间、真实摘要和明确来源。无当前 desired 时始终 null。
- Grafana 通过独立合成规则和隔离路由发 firing/resolved；验证队列持久接收、自动创建的会话 ID、实际执行的 `ccloud_l4`、同 run 证据引用、SSE 事件及不可变最终报告。
- 不以 ACK、idle、查询成功或独立日报结果代替整链通过。L4 当前快照不证明历史故障原因或完整业务健康。
- 重投不产生重复分析报告；原正式告警规则、通知路径、日报配置和记忆保持。清理临时规则，确认没有遗留 firing。

## 证据与边界

现场内部标识、观测和配置快照只保存在私有验收目录；公开工单只记录通用结果。无需新增 Kubernetes Secret、不转存本机管理员 CCloud 凭据。原服务单副本、外部 POST 提交不确定窗口和附件维护边界沿用既有文档，不扩大为本次可靠性承诺。
